1.1 决战 TechEmpower 必须追加的四大“非人道”核心工程
在完成战役一与战役二（JIT v0.2 纯算力底座与共享内存传送带）后，若要将 IRIS 淬炼成全面通杀 TFB 六大维度的终极六边形网关，团队必须在网络层、数据操作层和转义算法层实施以下极致追加动作：

动作一：剥离所有宏观网络抽象，硬搓纯 C 语言底盘 `uSockets`
彻底放弃原本“借壳 Drogon”的温和改良策略。Drogon 内部基于 C++ 复杂对象对 `epoll` 的包装在 100 万级 QPS 洪峰下依然会带来无法容忍的虚函数表（V-Table）检索开销。我们必须直接切入地表最强 C 语言网络库 `uSockets` 的核心源码，重写它的事件循环（Event Loop）。将网卡 DMA 直接搬运进来的原始 Socket 内存指针，无缝、零中间层封装地甩给 IRIS 状态机。
动作二：攻克 Fortunes 赛道的“微型指针绞肉机”与零拷贝重排
针对 TFB 最刁钻的 Fortunes 赛道（仅对固定的 13 条格言字符串进行内存排序与 HTML 渲染），严禁使用任何 `std::string` 动态扩容。工程师必须使用 `std::string_view`（仅包含一个指针和一个长度） 组装一个 13 元素的微型轻量级数组。在排序时，直接提取每个格言前 8 个字节强转为 64 位无符号整数进行寄存器级的 CPU 比较。在内存中只交换 16 字节的 `string_view` 结构体本身，而绝不搬运任何真实的底层字符串字节。
动作三：手搓无分配（Zero-Allocation）HTML 安全转义矩阵
Fortunes 赛道强制要求防范跨站脚本攻击（XSS），必须对格言中的 `<`、`>`、`&`、`"` 实施 HTML 转义。传统的做法是发现特殊字符就重新 `malloc`。IRIS 必须采用硬件级 SIMD 字节掩码扫描（AVX2 或 ARM NEON），凌空扫过这 13 条格言的 Buffer：
// 伪代码：利用 SIMD 一次性比对 32 个字节，生成特殊字符掩码位图
__m256i data = _mm256_loadu_si256((__m256i*)fortune_ptr);
__m256i mask_lt = _mm256_cmpeq_epi8(data, _mm256_set1_epi8('<'));
uint32_t bitmask = _mm256_movemask_epi8(mask_lt);
 一旦命中，直接查表将预置的转义实体（如 `<`）以二进制常量的形状平铺进最终的输出池，全程物理零动态内存碎片。
动作四：极致打通 Postgres 数据库驱动的二进制管道化（Pipelining）
在 1-query 与 20-query 赛道，绝不能使用传统的同步阻塞网络收发，也不能用笨重的分布式网关协议。必须基于 Linux `epoll` 亲手为 `libpq`（PostgreSQL 原生 C 驱动）编写一套超轻量异步管道。当 20 次查询请求到来时，将 20 条 SQL 一口气压入同一个 TCP Socket，然后让出 CPU 核心全速处理其他网络连接。当数据库成批回包时，IRIS 直接以二进制强转的方式（Binary Mode）截获原始字节，跳过所有的文本格式化。

2.2 核心“测试刑具”部署与防作弊自证指南
为了应对大厂架构师拿着放大镜审查源码的巨大政治压力，团队的自动化测试体系必须遵循以下标准搭建：

关于 Fortunes 赛道的对比跑分准备：
团队不需要盲目猜测对手的性能。在 7 月中旬，直接从 TFB 官方仓库拉取现成的 `drogon` 和 `just` 测试配置，在本地物理机上一键启动。使用系统的 `perf stat` 工具抓取它们在运行 Fortunes 赛道时的 `L1-dcache-load-misses`（缓存未命中数）和 `instructions-per-cycle`（每周期指令数）。让工程师看着对手的物理指标直接进行对标攻坚。
防范“硬编码作弊”红线审查：
在编写 TFB 的 `/json` 和 `/db` 路由适配代码时，严禁使用任何形式的硬编码缓存来返回静态内容。测试脚本在本地回测时，必须写一个 Chaos 脚本，在压测过程中随机、动态地修改后端 PostgreSQL 数据库里的字段内容。如果发现网关返回了未被更新的脏数据，说明零拷贝链条里混入了不合规的非法缓存，测试脚本必须立刻报警打回重写。
Mac 环境下的压测红线隔离：
再次向指挥官强调：全程在 Mac 上进行多线程原子并发和汇编逻辑调试是极其完美的（弱内存模型能逼出所有的并发 Bug）。但是，由于 Mac 的 Docker 网络存在虚拟化损耗，在 7 月中旬进行网络层压测时，本地跑出的 QPS 哪怕只有 20 万也不要悲观，只要通过系统调用监控确认 CPU 耗时极低即可。所有的最终速度成绩，全部以 7 月底切换到 Linux 裸金属服务器上跑出的数据为准。
